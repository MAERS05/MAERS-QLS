# MAERS QLS

**量化生活，规划时间。** MAERS QLS 将 Schedule 时间管理和 QuantiLife 生活量化整合在同一套本地数据与界面基础上，适合希望安排计划、记录实际投入并回顾生活趋势的个人用户。

| 入口 | 功能 |
| --- | --- |
| [门户](index.html) | 进入子系统、配置默认入口、业务备份、设备互传 |
| [Schedule](MAERS-Schedule/index.html) | 周历规划表、自定义时间列、短中长期任务、进行中多任务分段计时 |
| [QuantiLife 记录](MAERS-QuantiLife/index.html) | 步数、睡眠、饮水、饮食、时间与心情记录，设定期望 |
| [QuantiLife 报告](MAERS-QuantiLife/report.html) | 趋势、分类/标签排行、单一与并行事项分析 |

纯前端，无需自行部署业务服务器或注册应用账户。支持 PWA 安装与离线使用，主要数据保存在浏览器 IndexedDB 中；也提供 Windows 桌面启动器。设备配对使用本地固定版本 PeerJS 客户端访问官方公共服务，连接码方式不依赖公共服务。

> 请一次只在一个标签页编辑。保存后，先处理其他页面的未保存内容，再刷新继续操作。数据按浏览器配置和访问源隔离；固定使用相同访问地址，更换设备、地址或清理浏览器数据前导出业务备份。项目不提供云端同步。

规划表右侧的“默认”是占位列。点击列头，在弹窗中创建“生活、工作、假期”等自定义名称，再添加时间块；选择名称即可切换对应模板。QuantiLife 的设定按钮显示同一名称，时间分配随所选模板更新，实际日期安排保持独立。旧期望列有内容时自动迁入“原期望”模板。

## 局域网设备互传

手机、平板和电脑均可作为发送端或接收端，无需自行部署服务器或文件中转。使用支持 WebRTC、IndexedDB 的现代浏览器；两端打开各自原来存有数据的项目入口，连接允许设备互访的同一局域网，先暂停正在运行的计时任务。

默认“设备配对”由 PeerJS 官方公共服务协助，无需你部署或承担其他使用者的服务账号额度；两端需要能联网访问该服务，并打开门户的互传弹窗。可先修改并保存本机名称。

1. 接收端选择“接收其他设备”，自动显示 3 位配对码；发送端选择“发送本机数据”，输入对方的配对码并点击连接。
2. 双方核对设备名称并点击“确认配对”。应用分别保存对方的设备记录与配对凭据，然后自动交换完整连接信息。
3. 发送端点击“发送本机数据”；接收端核对预览并确认覆盖。发起连接时所选的发送/接收方向决定本次方向，另一端自动适配。
4. 以后双方打开互传弹窗，点击“已配对设备”里的目标即可重连。页面关闭后不保持后台在线；清理浏览器数据、更换访问源或一端删除配对记录后，需要重新添加设备。

公共服务是共享资源，短码可能被占用，点击“重新配对”即可换码；“重连服务”与“重新配对”位于弹窗底部。同一本机设备只开一个互传窗口，避免重复注册。服务不可达或离线时可切换到“连接码配对”，步骤如下；切换方式会结束当前配对。配对确认超时为两分钟，连接过程中也可取消或关闭弹窗。已配对设备可单独删除。

1. 两端在门户点击“设备互传”（双向箭头），选择“连接码配对”，分别选择发送和接收。
2. 选择发送端后自动生成连接码，将整段连接码复制给接收端；接收端粘贴后生成应答码，再将整段应答码复制回发送端。
3. 发送端粘贴应答码并点击连接；显示“已连接”后点击“发送本机数据”。
4. 接收端核对记录数量，点击“备份并覆盖”；发送端显示“对方已确认并保存”才表示接收成功。

每次单向传送当前完整业务快照，包含自定义时间列，接收端独有的业务记录会被删除。接收前只作预览，不会提前改动本机数据；空快照会明确提示清空。外观、报告视图状态等本机设置不在互传范围内。覆盖前自动保留一份恢复副本，可在互传弹窗中恢复；恢复本身也保留替换前的数据，副本仅保留最近一次。

连接码只用于本次连接，业务数据在连通后经设备间加密通道传送，不使用 STUN/TURN 服务或公网中继。项目资源已完整离线缓存时，可在没有互联网、但局域网仍可互访的情况下使用。两端保持页面在前台；连接失败时检查访客 Wi-Fi 隔离、VPN 或防火墙，再重新配对。不同设备的浏览器能力和网络策略可能影响直连，项目不提供后台自动同步。

设备配对也显式禁用 STUN/TURN，不自动中转业务数据；同一局域网仍需允许设备互访。配对服务会处理设备编号和网络连接信息；配对凭据在设备间加密通道内交换，设备记录保存在本机 `qls_paired_devices`，不随业务备份、导入、互传或恢复传播。公共服务连接中断后，已经建立的业务通道可继续使用，新配对需重试。共享服务不保证持续可用；[官方使用说明](https://peerjs.com/server/cloud)建议高流量应用自行托管，本项目未部署自有服务。

覆盖后其他已打开页面会提示保留输入并刷新；旧页面的写入和旧草稿自动恢复会被阻止，避免把覆盖前的数据重新写回。详细边界见[数据保障与存储迁移](<_说明/数据保障与存储迁移.md>)。

## 启动

开发环境需要 Node.js ≥ 22。浏览器使用支持原生 ES 模块、IndexedDB 和原生 dialog 的现代版本；真实浏览器测试使用本机 Chrome 或 Edge。

在项目根目录执行：

```powershell
npm ci
npm start
```

默认只监听本机，起始端口为 8081，会打开浏览器；以启动日志给出的地址为准。`npm start` 先刷新预缓存清单。开发依赖用于检查和测试，浏览器运行时无需它们。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 改为 `0.0.0.0` 可供局域网设备访问 |
| `PORT` | `8081` | 配置起始端口；已有 QLS 服务时复用，其他程序占用时顺延 |

PowerShell 配置示例：

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '3000'
npm start
```

变量影响当前终端及其子进程；用完可关闭终端。端口改变也会改变浏览器数据所属的访问源。

## 命令与验证

命令定义见 [package.json](package.json)，检查范围和覆盖率要求统一见[开发规范](<_说明/开发规范.md>)。

| 命令 | 用途 |
| --- | --- |
| `npm start` | 经 [scripts/dev-server.js](scripts/dev-server.js) 启动本地静态服务 |
| `npm run lint` | ESLint 检查 |
| `npm test` | 单元、页面集成和静态契约测试，自动预更新缓存清单 |
| `npm run test:coverage` | 全量测试与逐文件覆盖率门槛检查 |
| `npm run test:e2e` | 真实浏览器测试；无可用浏览器时跳过，需留意实际结果 |
| `npm run build:precache` | 由运行时资源生成 [precache-manifest.js](precache-manifest.js)，无需手改 |
| `npm run build` | 生成仅包含运行时资源的 `dist/` |
| `npm run build:exe` | 通过 [scripts/build-desktop-app.js](scripts/build-desktop-app.js) 生成 `MAERS-QLS.exe` 和 [common/ui/icon.ico](common/ui/icon.ico)，并将启动器复制到系统桌面 |

可用 `E2E_CHANNEL=chrome` 或 `msedge` 指定测试浏览器；PowerShell 中按上述环境变量方式设置。

## 安装和发布

- **PWA**：通过本机 HTTP 或线上 HTTPS 访问，浏览器支持时选择“安装应用 / 添加到主屏幕”。首次完整缓存完成后才具备离线打开能力。
- **Windows 启动器**：已有 `MAERS-QLS.exe` 时可双击启动。运行依赖本机 Node.js、Chrome/Edge 和项目文件；它不是将项目及 Node 打包进单个可移植 exe。构建会调用 Windows .NET C# 编译器生成窗口启动器。
- **静态部署**：运行 `npm run build` 后发布 `dist/` 内容，不上传整个仓库。当前 [vercel.json](vercel.json) 已配置该构建命令和输出目录；其他静态主机需提供正确的 JS MIME 类型并保持相对路径。线上 HTTPS 用于 PWA/Service Worker。

桌面窗口关闭时启动器会停止其后台服务，重复启动会尝试唤醒既有窗口。源文件在本仓库中维护，`dist/` 与启动器均为构建产物。
