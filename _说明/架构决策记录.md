## ADR-001：原生 ES 模块与集中兼容接口

**状态：已采用，按当前实现补录。**

### 问题

早期大文件承载多项职责，`MS / QL` 通过原型继承公共对象；页面用手写脚本顺序初始化服务和视图。拆分文件后，如果继续靠全局对象和加载顺序连接，依赖仍然不直观，时间轴与主页面之间还会形成双向调用。

### 当前方案及原因

- 浏览器按原生 `import` 装载具名职责模块，页面各自只有一个模块入口，直接表达依赖并消除手写脚本顺序。
- 页面协调器注入编辑回调，拖拽和编辑器工厂接收上层操作；视图不反向读取主页面的全局方法。
- 保留 `runtime.js / api.js / facade.js` 兼容组合，由入口发布 `window` 接口；内部模块不导入这些门面，避免重新聚成隐式依赖中心。
- 保持运行时零第三方依赖和静态资源发布方式，改动可以逐职责验证，不需要引入新框架来表达当前页面交互。

### 备选方案比较

| 方案 | 优点 | 代价或不适合之处 |
| --- | --- | --- |
| 继续全局脚本并维护顺序清单 | 改动少，兼容原组织方式 | 拆分后的依赖仍隐藏，加载与业务耦合，难以检查独立模块 |
| 原生模块 + 明确页面入口 | 浏览器直接支持静态依赖，维持现有静态发布路径 | 文件请求增多，需要递归预缓存模块图，测试装载方式要适配 |
| 引入框架与打包器重写 | 组件、状态和构建生态成熟 | 当前任务是理清现有边界，全面迁移成本和回归范围显著扩大 |

### 代价和边界

模块内部仍使用可测试的服务对象，而非所有状态都变为不可变数据；兼容对象也仍可读到同一服务状态。这是兼容边界，不是鼓励新业务依赖全局接口。

jsdom 测试装载器只支持项目当前使用的模块语法子集，例如具名导入和导出声明，并显式拒绝循环依赖；它不是完整浏览器模块运行时。新增默认导入、再导出或异步装载等机制时，需要同步调整装载器与静态分析，并以真实浏览器测试验证语义。

未来若模块请求数量或资源缓存成本成为经测量确认的瓶颈，可以在保留职责边界的基础上评估打包；没有必要为了保持此决策永久排除构建工具。

[四个页面入口导航](文件功能说明.md)、[facade.js](../common/js/facade.js)、[modules.js](../tests/helpers/modules.js)、[architecture.test.js](../tests/unit/architecture.test.js)、[静态契约测试](../tests/static/contracts.test.js)。

## ADR-002：稳定存储门面、IndexedDB 事务与共享投影

**状态：已采用，按当前实现补录。**

### 问题

页面需要同步读取本地数据，但 IndexedDB 是异步接口。计时完成可能影响多个日期及并行事件；若先保存任务，再独立写入日记录，中途失败就会出现已完成任务和量化记录不一致。跨标签页的陈旧编辑也可能覆盖其他页刚提交的内容。

### 当前方案及原因

- 使用身份稳定的 `storage.store` 门面，启动时载入内存镜像并切换后端；页面通过就绪入口延后首次读取，领域接口保留同步读取方式。
- 区分乐观镜像和已提交镜像，写入串行排队，事务内对本页基线、提交值与最新磁盘值三方合并。同字段冲突拒绝，确认成功后才推进编辑基线。
- 计时任务与全部受影响日记录在同一事务中提交。`timer-events.js` 提供纯投影，事务层和桥接层分别使用，数据库不依赖桥接内部方法。
- 标签经单一仓库读写，按存储版本失效缓存，读取快照避免跨模块直接改缓存。
- 草稿使用文档所有权和 Web Locks，缺少锁能力时采用明确离页标记；初始化失败进入保护锁定。

### 备选方案比较

| 方案 | 优点 | 代价或不适合之处 |
| --- | --- | --- |
| localStorage 作为唯一后端 | 同步接口简单 | 大容量、事务、多页冲突处理能力有限 |
| 所有领域读取改为异步直读 IDB | 减少完整内存镜像 | 页面和渲染链路需要广泛异步化，仍需解决编辑快照与多键事务 |
| 任务提交后异步补写派生记录 | 保存逻辑表面简单 | 部分失败或页面关闭会留下不一致，不能保证多日整体回滚 |
| 事务内合并和投影 + 同步镜像 | 保留页面读取方式，保证任务与派生记录一致 | 内存有两类镜像，队列、冲突和草稿恢复需要专门测试 |

### 代价和边界

同步受理不等于持久化成功，需要 `flush()` 确认。BroadcastChannel 只负责同源页面通知，不是分布式同步协议。保留单页编辑建议；兼容 localStorage 后端提供尽力回滚，但不宣称具有与 IndexedDB 相同的原子性。

该方案保护的是当前浏览器源内的数据一致性，不提供账户、跨设备备份或浏览器清理后的恢复。如果未来引入远端同步，需另立决策说明数据所有权、版本和冲突模型，不能把广播机制直接当作云同步。
