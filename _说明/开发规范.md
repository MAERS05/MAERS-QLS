# 开发规范

本文件是项目开发约束的唯一书面来源。README 负责使用入口，其他说明文档解释流程、机制与设计原因，不另设一套规则。规则发生变化时先更新本文件，再调整引用和实现。

## 模块与职责

1. 浏览器业务代码使用原生 ES 模块，依赖通过相对路径、静态 `import` 声明；每个页面只声明一个模块入口，首屏 `theme-boot.js` 除外。
2. 内部模块直接导入职责模块，不读取 `window.QLS / MS / QL / MAERS_BRIDGE`，不导入 `runtime.js`、`api.js`、`facade.js` 获得整套能力，也不通过原型继承公共命名空间。兼容接口由页面入口集中发布。
3. 模块依赖保持无环。页面协调器连接视图与服务；视图需要打开编辑器或调用上层操作时，使用注入的回调。纯数据计算不接触 DOM，存储事务规则不依赖桥接界面或桥接内部方法。
4. 分类、存储键、日期解析、记录归一化、标签存取分别复用既有提供者；新增功能前先查[文件功能说明](文件功能说明.md)，避免平行维护同一契约。
5. 拆分以职责和变化原因作为边界，不以行数作为硬性阈值。运行时保持零第三方依赖；新增依赖或构建步骤属于架构变更，需同步记录取舍。

## 数据写入与兼容

1. 业务持久化经稳定的 `storage.store` 门面进行。除存储后端、迁移、草稿和首屏设置引导等基础设施外，业务模块不直接操作 IndexedDB 或 localStorage。
2. `set/remove` 表示写入受理，成功反馈以 `flush()` 确认为准。编辑器从 `getCommitted()` 获取基线；远端通知不能替换已打开编辑器的原基线，提交成功前不能清空用户输入。
3. 任务变化与受影响的派生日记录保持同一 IndexedDB 事务；跨系统导入经一次批量事务完成。不能把原子操作改为几个独立的后续保存。
4. 手动内容与同步派生内容的归属保持清楚；冲突时保留输入和恢复副本，不静默覆盖。迁移只在新副本提交成功后清理旧副本，初始化失败不允许业务在空后端继续写入。
5. 数据结构变更需同时处理归一化、旧数据迁移、备份导入及回归用例；schema 版本和迁移记录配套修改。具体结构与行为见[数据保障与存储迁移](数据保障与存储迁移.md)。

## 界面与模板

1. 动态 HTML 使用 `dom.html` 标签模板，经 `dom.setHTML / insertHTML` 写入；`dom.raw` 仅用于可信静态片段，不接收用户输入。普通文本优先使用 `textContent`。
2. HTML 模板中的 ARIA 布尔属性插值显式调用 `String()`，避免 `false` 被模板转为空字符串。
3. 弹窗使用原生 `<dialog>`，经 `ui.openDialog / closeDialog / bindDialog` 管理。共享定位、遮罩与动画在公共组件样式中维护。
4. 显隐使用 `hidden` 属性。`!important` 仅允许出现在 `base.css` 的 `[hidden]` 显隐规则。
5. 选中、折叠等交互状态使用对应 ARIA 属性，并保持键盘行为与焦点可用；不为同一语义增加不必要的平行状态。
6. 新增业务颜色优先经 CSS 自定义属性传递，不把用户数据拼进样式。图表几何、拖拽位移等动态数值按组件需要设置；现有排行条仍生成计算后的宽度和渐变样式，不作为复制任意内联样式的通用模式。

## 验证要求

| 改动类型 | 验证范围 |
| --- | --- |
| 纯文档 | 检查引用、示例、术语与实现一致；运行已有静态契约测试，无需新增业务测试 |
| 公共逻辑、领域服务、页面行为 | ESLint、相关单元/集成测试；新增页面行为附对应交互用例；交付前运行全量测试和覆盖率 |
| 模块边界、入口、资源路径 | 增加静态契约验证，检查构建及预缓存是否包含完整模块图 |
| IndexedDB、跨页同步、草稿、原生 dialog、离线行为 | 增加或更新对应真实浏览器 E2E，另有故障、冲突或重试场景时验证失败路径 |
| 桌面启动器 | 相关 Windows 构建测试，必要时在 Windows 实机验证窗口生命周期 |

测试分层：公共/领域逻辑放 `tests/unit/`，页面交互放 `tests/integration/`，跨文件约束放 `tests/static/`，真实浏览器能力放 `tests/e2e/`。

命令见 [README](../README.md)。覆盖率门槛由 `package.json` 配置：行 80%、分支 70%、函数 75%。CI 执行 ESLint、清单一致性和覆盖率，Windows 作业验证桌面构建；E2E 需另行运行。浏览器不可用而跳过时，报告跳过原因，不能记作通过。

## 资源与发布

1. 运行时资源变化后执行 `npm run build:precache`，提交生成的 `precache-manifest.js`，不手写版本号或资源表。纯文档变动不需要改变运行时缓存版本。
2. 发布目录由 `npm run build` 生成，仅发布 `dist/`。不手工修改发布副本；测试、开发脚本、仓库元数据及说明文档不进入运行时清单。
3. 新资源命名遵守发布白名单。文件名中的 `backup`、`private`、`secret`、`temp`、`tmp`、`test`、`tests` 等保留片段会被过滤；业务传输模块沿用 `data-transfer.js / json-transfer.js`。
4. 与 Cloudflare 交互时，项目存在 Wrangler 配置文件则使用 Wrangler，否则使用 cf CLI。当前仓库没有 Cloudflare 发布配置，不推断或新增部署目标。
